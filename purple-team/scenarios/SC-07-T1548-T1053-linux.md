## Objectif

Appliquer à Linux la méthode de SC-05 et SC-06 : attaquer depuis PURPLE. L'accès initial simulé est une session SSH
avec des identifiants déjà connus de l'attaquant. Depuis cette session, il utilise `sudo`, puis pose un fichier
cron pour garder un accès.

## Ce qu'il a fallu corriger avant

- L'agent de LINUX01 était dans le groupe Wazuh `default`, dont la configuration ne contient que des chemins
  Windows (`%WINDIR%`, registre). Elle n'avait aucun effet sur un serveur Linux, et rien ne surveillait les
  répertoires cron. Un groupe `linux` a été créé ([`agent-linux.conf`](../../wazuh/agents/agent-linux.conf)), avec
  une surveillance en temps réel de `/etc/cron.d`, `/etc/cron.{daily,hourly,weekly,monthly}` et `/var/spool/cron`.
- La carte de gestion (`enp0s9`, 10.10.10.111) n'était pas dans la configuration réseau persistante
  (`/etc/netplan/01-socforge.yaml`). Corrigé.

## Test

```python
import paramiko
c = paramiko.SSHClient()
c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect('10.10.10.111', username='socadmin', password='...')
c.exec_command('echo ... | sudo -S whoami')                       # T1548.003
c.exec_command('echo ... | sudo -S tee /etc/cron.d/socforge-test') # T1053.003
```

## Méthode de vérification

Les alertes sont recherchées par agent (`(linux01)`) et non par mot-clé seul. Une commande `sudo` tapée sur la
console du manager (agent 000) déclenche aussi la règle 100200 et peut prêter à confusion sans ce filtre.

## Lecture côté défense

Les deux détections reposent sur des sources différentes : le journal d'authentification pour `sudo`, la
surveillance d'intégrité en temps réel pour les répertoires cron. La seconde ne couvre que les chemins déclarés
dans [`agent-linux.conf`](../../wazuh/agents/agent-linux.conf) (`/etc/cron.*`, `/var/spool/cron`, `/etc`).

Depuis le 07/10, l'agent Velociraptor de LINUX01 permet aussi de rechercher un indicateur dans ses journaux et ses
crontabs, et d'isoler le serveur (voir SC-15).

## Nettoyage

`/etc/cron.d/socforge-test` supprimé juste après la validation de l'alerte.
